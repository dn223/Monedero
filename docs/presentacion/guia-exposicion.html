Monedero — guía para entender y exponer

Monedero electrónico prepago de circuito cerrado · Gestión de la Calidad del Software · UFG

1. ¿Qué es?

Es una tarjeta prepago como la de un supermercado. Cada tarjeta tiene un número de 16 dígitos y un saldo; se recarga en caja y se gasta en compras del mismo comercio (circuito cerrado: no hay transferencias entre personas). Es un proyecto académico, pero está construido como si manejara dinero real: no se puede perder, duplicar ni inventar un centavo.

Regla del dineroEn palabras simples
Centavos enteros$7.35 se guarda como 735. Nunca decimales, así no hay errores de redondeo.
RecargasSolo múltiplos de $5. Cobros mayores que cero y nunca más que el saldo.
PINLas compras de más de $25 piden el PIN del titular.
Todo o nadaCada cobro bloquea la tarjeta, revisa el saldo y registra el movimiento en una sola transacción.

Libro inalterableLos movimientos no se pueden editar ni borrar. El saldo siempre es igual a la suma de los movimientos ("Todo cuadra").

Titular ≠ tarjeta. El titular es la persona (nombre, correo, contraseña, PIN). La tarjeta es el medio de pago (número, saldo, estado). Si pierde la tarjeta, se le repone otra con el mismo saldo; la persona sigue siendo la misma.

4. ¿Por qué no hay cámara ni tarjetas físicas todavía?

La meta final (Fase 7) son tarjetas con chip NFC que la caja lee al acercarlas. Mientras tanto, la tarjeta se identifica con códigos: la caja la elige de la lista de tarjetas activas o escribe su número, y el servidor verifica que sea válida (número, identificador del chip y firma digital que solo el servidor puede comprobar). El titular también puede pagar desde su celular con "Pagar en caja", escribiendo el código de 6 dígitos de la caja, igual que se le paga a una tienda.

5. Módulos (lo que pidió el ingeniero)

Desde Administración → Módulos se activa o desactiva cada parte de la app, al instante y para todos. Lo importante: el backend lo hace cumplir. Si un módulo está apagado, la app oculta el botón y la API rechaza la operación (MODULE_DISABLED) aunque alguien la llame directamente. Cada cambio queda registrado con quién y cuándo.

MóduloSi se apaga…
Asistente virtualDesaparece el botón "Asistente" y la API no responde preguntas.
Registro de titularesNadie nuevo puede crear cuenta.
Pago con código de cajaEl titular ya no puede pagar desde el celular; solo en caja.
QR de la tarjetaLa API deja de enviar los datos que forman el QR.
Cambio de PINEl titular no puede cambiar su PIN desde la app.

Siempre activos (no se pueden apagar): recargas, cobros, reporte de pérdida y reposición, porque protegen el dinero. En la exposición di "módulos", no "panel de administrador".

¿Cómo funciona el asistente?

  1. El titular escribe una pregunta en el chat (o toca una sugerencia).
  2. La API revisa primero que el módulo esté activo; si no, responde "desactivado".
  3. Limpia el texto (sin acentos ni mayúsculas) y busca palabras clave para saber de qué trata: saldo, movimientos, recargar, pagar, QR, PIN, pérdida, reposición, saludo o gracias. Si hay varias, la pérdida tiene prioridad.
  4. Lee los datos reales del titular en la base: su tarjeta, su saldo y su último movimiento.
  5. Responde con esos datos ("Tu saldo es $12.65") y ofrece 3 preguntas sugeridas. No menciona funciones de módulos apagados.
Es un asistente por reglas: no usa inteligencia artificial externa, no cuesta dinero, no envía datos a terceros y no guarda las conversaciones. Si no entiende, dice con qué temas sí puede ayudar. Más adelante podría conectarse a un modelo de lenguaje sin cambiar la app.

7. Preguntas que puede hacer el ingeniero

¿Dónde está desplegado? La API sirve la app web y un túnel de Cloudflare la publica con un link https. Corre en la laptop del equipo con Docker; el servidor en la nube (Contabo) está preparado pero no contratado.

¿Qué pasa si se cae la red a mitad de un cobro? La operación lleva una clave única; si se reintenta, la base devuelve el mismo resultado sin cobrar dos veces.

¿Qué pasa si dos cajas cobran a la vez a la misma tarjeta? La base bloquea la tarjeta durante cada cobro. Probamos 1,000 cobros simultáneos: nunca quedó saldo negativo.

¿Alguien puede inventar una tarjeta? No: cada tarjeta lleva una firma digital hecha con una llave que solo vive en el servidor.

¿Y si alguien roba el código de una caja? Administración revoca la caja y el código deja de funcionar al instante, junto con su sesión.

¿Cómo prueban la calidad? 83 pruebas automáticas (reglas, API contra PostgreSQL real y pantallas) corren antes de cada cambio con dart run tool/check.dart.

8. Para tenerlo corriendo

  • Levantar y obtener el link: dart run tool/share.dart (imprime el link y su QR).
  • Correos de prueba (solo en la laptop): http://localhost:8025.
  • Apagar todo: dart run tool/down.dart. Borrar todo y dejar solo administración: dart run tool/reset_demo.dart (luego apagar el asistente otra vez).
  • La laptop debe quedar encendida y con Internet: el link vive en ella y cambia si se recrea el túnel.
